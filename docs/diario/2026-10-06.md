# 2026-10-06

## Hecho
- **Repositorio público**: historial escaneado con gitleaks (27 commits, sin secretos) y aviso de
  derechos reservados en `LICENSE` (inglés y español).
- **Instalación de Argo CD v3.5.3** con Kustomize a partir del manifiesto oficial con versión fijada
  (`gitops/bootstrap/argocd`), en el namespace `argocd`.
- **Patrón App of Apps**:
  - `root-app.yaml`: aplicación raíz, la única que se aplica a mano.
  - `appsets/argocd.yaml`: Argo CD se gestiona a sí mismo desde Git.
  - `appsets/apps.yaml`: ApplicationSet que crea una aplicación por cada carpeta de `gitops/apps/`.
- **Aplicación de demostración `demo-app`** (`traefik/whoami:v1.12.0`): Deployment con réplicas,
  límites de recursos y contexto de seguridad restrictivo (sin root, sistema de archivos de solo
  lectura, sin capacidades), y su Service.
- Verificado el **reparto de carga** entre réplicas (respuestas de pods distintos).
- **GitOps verificado en los dos sentidos**:
  - Git → clúster: `replicas: 2 → 3` en Git; el tercer pod apareció solo tras el merge.
  - Clúster → Git: escalado manual a 1 réplica; Argo CD lo devolvió a 3 en menos de un segundo (`selfHeal`).
- **Script `scripts/bootstrap.sh`** y objetivo `make bootstrap`, integrado en `make deploy`.

## Problemas y soluciones
- **Problema:** el repositorio era privado y Argo CD no podía leerlo.
  **Solución:** escaneo del historial con gitleaks y publicación del repositorio (alternativa
  descartada: deploy key de solo lectura).
- **Problema:** en el commit del `LICENSE` entró también el borrado de `values.yaml`, y el resto
  del trabajo de Argo CD quedó sin commit en una rama ya fusionada.
  **Solución:** mover los cambios pendientes a una rama nueva desde `main` actualizado.
- **Problema:** `podman search` mostraba las versiones en orden alfabético (`v1.9` al final).
  **Solución:** filtrar y ordenar con `sort -V`.
- **Problema:** el bootstrap fallaba con `Apply failed with 1 conflict ... argocd-controller`.
  **Causa:** Argo CD ya se gestionaba a sí mismo y `kubectl` intentaba quitarle la propiedad de sus campos.
  **Solución:** el script solo instala Argo CD si no existe; si existe, lo deja en manos de Argo CD.

## Decisiones
- Repositorio público, sin licencia libre (todos los derechos reservados).
- Argo CD instalado con Kustomize y el manifiesto oficial (sin Helm por ahora).
- `prune: false` en la aplicación de Argo CD (evita que un error en Git lo borre) y `prune: true`
  en las aplicaciones (borrar una carpeta retira la app).
- `ServerSideApply` para Argo CD por el tamaño de sus CRD.
- ApplicationSet de plataforma aplazado hasta tener componentes en `gitops/platform/`.
- Criterio de ubicación: lo necesario para recuperar el clúster (acceso, identidad, VPN, copias) va
  fuera de Kubernetes; aplicaciones y servicios de plataforma, dentro.

## Fuentes
- Versión de Argo CD: API de releases de GitHub del proyecto argoproj/argo-cd.
- Manifiesto oficial de instalación de Argo CD (`manifests/install.yaml`, v3.5.3).
