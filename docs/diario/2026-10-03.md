## Problemas y soluciones
- **Problema:** `ansible: command not found`.
  **Solución:** instalar el paquete `ansible` (incluye colecciones), no solo `ansible-core`.
- **Problema:** `stdout_callback = yaml` depende de un plugin obsoleto.
  **Solución:** usar `callback_result_format = yaml`.
- **Problema:** el plan seguía mostrando `agent.enabled = false`.
  **Causa:** el cambio no se había guardado en el archivo.
  **Solución:** editar, verificar con `grep` y repetir el plan.
- **Problema:** pre-commit falló con `PermissionError` y el commit no se hizo.
  **Causa:** dos archivos del rol creados con `sudo` (propiedad de root).
  **Solución:** `sudo chown ngtn:ngtn` y localizar otros casos con
  `find . -not -user ngtn`. Regla: nunca usar `sudo` dentro del repositorio.
- **Problema:** GitHub no ofrecía crear el Pull Request.
  **Causa:** la rama se había subido antes sin commits (por el fallo anterior).
  **Solución:** crear el PR manualmente desde *Pull requests → New*.

## Decisiones
- El inventario de Ansible se genera siempre desde Terraform; no se edita a mano.
- Grupos del inventario según el campo `role` del mapa `vms`.
- El agente QEMU se instala con Ansible y después se activa en Terraform.
- Los comandos de Ansible se ejecutan desde `ansible/` para usar su `ansible.cfg`.
- Ensayo con `--check --diff` antes de aplicar cambios en las VMs.
- El hardening de SSH usa un archivo propio en `sshd_config.d/` en lugar de modificar
  `sshd_config`; se valida con `sshd -t` antes de reiniciar el servicio.
- Al modificar SSH, mantener una sesión abierta como red de seguridad.
- El firewall se pospone hasta instalar k3s, para abrir solo los puertos que necesite.
