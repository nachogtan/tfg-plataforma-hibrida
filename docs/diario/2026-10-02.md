## Problemas y soluciones
- **Problema:** pre-commit bloqueó un commit por un archivo de 27 MB.
  **Causa:** la carpeta `.terraform/` (binario del provider) no estaba en `.gitignore`.
  **Solución:** `git restore --staged`, añadir la sección de Terraform a `.gitignore`
  (incluido `*.tfstate`) y repetir el commit.
- **Problema:** `Unable to create Proxmox VE API credentials`.
  **Causa:** en `.env` solo estaba el secreto, sin `usuario@realm!token=`.
  **Solución:** formato completo `terraform-prov@pve!terraform=<UUID>`.
- **Problema:** `Missing Proxmox VE API Endpoint` en una terminal nueva.
  **Causa:** las variables de `.env` no persisten entre terminales.
  **Solución:** `source .env` (mejora pendiente: direnv o Makefile).
- **Problema:** `terraform init` buscaba `hashicorp/proxmox`.
  **Causa:** el módulo no declaraba su provider.
  **Solución:** bloque `required_providers` con `source = "bpg/proxmox"` en cada módulo.
- **Problema:** aviso *Deprecated* en `proxmox_virtual_environment_download_file`.
  **Solución:** renombrado a `proxmox_download_file` antes del primer `apply`.
- **Problema:** commit hecho por error en `main`.
  **Solución:** `git branch <rama>` + `git reset --hard origin/main` + push de la rama.

## Decisiones
- Imagen base: Debian 13 *genericcloud* (ligera y preparada para cloud-init).
- IPs fijas para las VMs, porque sin agente QEMU Proxmox no puede informar de la IP.
- Agente QEMU desactivado en Terraform; se instalará con Ansible.
- Desarrollo con los recursos actuales del nodo; ampliación de RAM solo si las pruebas
  de varios nodos lo requieren.
