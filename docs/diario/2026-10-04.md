## Problemas y soluciones
- **Problema:** `pvesm set local --content ...` mostraba la ayuda en lugar de aplicarse.
  **Solución:** `pvesh set /storage/local --content iso,vztmpl,backup,import,snippets`.
  `--content` sustituye la lista completa, por lo que hay que incluir los tipos existentes.
- **Problema:** añadir el *vendor-data* obligaba a reemplazar la VM.
  **Causa:** cloud-init solo se ejecuta en el primer arranque.
  **Solución:** aplicarlo dentro de la reconstrucción completa.
- **Problema:** `terraform_fmt` reformateó archivos y detuvo el commit, y el push subió una rama vacía.
  **Solución:** `terraform fmt -recursive terraform/` antes del commit y encadenar `git commit ... && git push`.
- **Observación:** en modo `--check`, las tareas `command` se omiten; el ensayo del rol `k3s` es limitado.

## Decisiones
- Rol `k3s` propio con el instalador oficial (en lugar de la colección `k3s-ansible`),
  para entender y controlar cada paso.
- Versión de k3s fijada en `defaults`; cambiarla provoca la actualización en la siguiente ejecución.
- El rol solo reinstala si la versión instalada no coincide con la del código (idempotencia).
- Las pruebas de reconstrucción se ejecutan siempre desde código ya fusionado en `main`.
